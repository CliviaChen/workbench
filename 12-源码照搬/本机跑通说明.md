## 3. 本机做的改动（7 处，都可回滚）

### ① 新增引擎入口适配层 `12-源码照搬\引擎\`

外壳只认 `<工作台>\引擎\apps\cli\lib\bin.js` 这一个相对路径，而本机引擎在 asar 里。所以新建：

- `引擎\apps\cli\lib\bin.js` —— 转发器：用 `D:\DSH\DeepSeek Harness.exe` + `ELECTRON_RUN_AS_NODE=1` 去跑 asar 里的真 CLI，参数、stdout/stderr、退出码原样透传（token 能被外壳捕获）。
- `引擎\package.json`、`引擎\apps\cli\package.json` —— 只给外壳「版本信息卡」读，写 `0.2.2-rc.3`。

> 换成真正的引擎目录（DSH 源码 `pnpm` 构建产物，或 npm 装的 `@deepseek-ai/dsh`）时，**删掉 `bin.js` 换成真入口即可**，外壳其它地方不用动。
> 路径可用 `DSH_DESKTOP_EXE` / `DSH_ASAR_CLI` 覆盖。

### ② 三个目录联接（junction）

模板的数据在 `引擎数据\.dsh`，但外壳和脚本默认按 `引擎\.dsh`、`引擎\场景记忆`、`引擎\插件` 找东西：

```
12-源码照搬\引擎\.dsh      →  ..\引擎数据\.dsh
12-源码照搬\引擎\场景记忆   →  ..\引擎数据\.dsh\场景记忆
12-源码照搬\引擎\插件       →  ..\插件
```

没有这三个联接，`sessions.mjs --check` 会去读一个空的 `引擎\.dsh` 而全部报「会话不存在」，记忆神经元面板也读不到数据。
神经元面板每个点/每条线分别是什么意思、以及新增的「文件夹模式」，见 [`说明/记忆神经元说明.md`](说明/记忆神经元说明.md)。
「命令」页右侧的 AI 面板现在直连桌面版 DSH（和桌面版同一批工作区/对话，实时双向），
其它场景仍用工作台自己的数据目录，见 [`说明/命令页直连桌面DSH.md`](说明/命令页直连桌面DSH.md)。

### ③ `启动.vbs`：端口 3080 + 固定 DSH_HOME

- `DSH_PORT` 从 `3083` 改成 **`3080`**。原因：外壳脚本（`建会话.mjs` / `sessions.mjs` / `会话改名.mjs`）的 token 正则和 `BASE`、以及 `renderer\index.html` 的 CSP `frame-src` **全都写死 3080**。改端口要同时改这 4 个文件，不如跟模板默认对齐。
- 新增 `DSH_HOME=引擎数据\.dsh`：引擎子进程继承父进程全部环境变量，若从「DSH 的终端」里启动，父进程带的 `DSH_HOME`（`C:\Users\<你>\.dsh`）会把引擎引到别的数据目录。

### ④ `外壳\main.js`：自动点掉「预览版说明」

0.2.2 在**新的 DSH_HOME** 上首次启动会弹全屏「预览版说明」模态框，挡住整个界面（面板注入全部落空）。在 `HARNESS_FIX_JS` 的 `fix()` 开头加了几行：找到文案为「继续 / Continue」的可见按钮就点一次（每个 webview 一次）。点完引擎会把确认写进 Host settings 的 `ui-settings-general.welcomeNoticeVersion`，以后不再弹。

### ⑤ 4 个场景 json 补 `sessionId`

`command.json` / `bilibili.json` / `self-review.json` / `pc-cleanup.json` 的 AI 面板原本只有 `sessionTitle` + `pinTarget`，没有 `sessionId`。已补上（`sessionTitle` 必须与引擎里标题逐字一致）：

| 场景 | 会话 id |
|---|---|
| 命令 | `session-42838fee-9831-4ddf-a53c-57cff7b4b166` |
| 命令 | `session-42838fee-9831-4ddf-a53c-57cff7b4b166`（命令页现直连桌面版 DSH，不再用这条） |
| 自我复盘 | `session-5e5f7efb-61f8-4744-bdf2-fd32fc25ab47` |
| 本地电脑 | `session-cd8b4aba-5837-43cd-9c99-cb19a664d583` |

### ⑥ 引擎 profile 补启动动画插件

`引擎数据\.dsh\profiles\web\cordis.patch.yml` 里挂了 `dsh-plugin-boot-anim`，但 profile 的 `node_modules` 里没有 → 每次启动报 `ERR_MODULE_NOT_FOUND`（只是警告，不拦启动）。已把 `12-源码照搬\插件\启动动画` 拷到：

```
引擎数据\.dsh\profiles\web\node_modules\dsh-plugin-boot-anim
```

### ⑦ 把桌面版已登录的账号凭证给工作台引擎

工作台引擎用的是**独立数据目录** `引擎数据\.dsh`，桌面上登录过的账号它看不到 ⇒ AI 面板会弹「等待登录」。已从桌面版复制：

- `C:\Users\<你>\.dsh\.credentials.yaml` → `引擎数据\.dsh\.credentials.yaml`
- `C:\Users\<你>\.dsh\llm-deepseek\` → `引擎数据\.dsh\llm-deepseek\`

原设备凭证备份在 `引擎数据\.dsh\.credentials.yaml.device-bak`；`引擎数据/.dsh/.credentials.yaml` 与 `llm-deepseek/` 都已在 `.gitignore` 里排掉，不会误提交。

> ⚠️ 这等于把账号令牌抄了一份到工作台目录。若不接受，删掉这两个文件、把 `.device-bak` 改名回去，然后**在 AI 面板里手动登录一次**，效果一样。

## 4. 启动与日常

```powershell
cd <工作台>\12-源码照搬
# 1) 双击 启动.vbs（或：外壳\node_modules\electron\dist\electron.exe .）
# 2) 确认三件事
Test-NetConnection 127.0.0.1 -Port 3080   # 引擎
Test-NetConnection 127.0.0.1 -Port 31238  # 界面静态服务
# 3) 自检（用引擎自带的 Node 24，否则 Node 版本那一项必红）
& 'D:\DSH\resources\runtime\primary-runtime\dependencies\node\bin\node.exe' 外壳\scripts\自检.mjs
# 4) 会话↔场景对照
$env:DSH_HOME = 'E:\luanyujia-workbench-main\12-源码照搬\引擎数据\.dsh'
node 外壳\scripts\sessions.mjs --check
```

**在 DSH 自己的终端/工具里跑这些脚本时，一定先 `$env:DSH_HOME` 指到 `引擎数据\.dsh`** —— 否则它会继承 DSH 宿主的 `DSH_HOME`（你的 `~\.dsh`），读到别人的会话表。在普通 cmd/PowerShell 窗口里没这个问题（有 ② 的联接兜底）。

### 新建/换会话

```powershell
$env:DSH_HOME='...\引擎数据\.dsh'
node 外壳\scripts\建会话.mjs --title "新场景名"
# ⚠️ 它只在「cwd 已注册成 workspace」时才把会话挂进侧边栏，否则会落进「未分组」
```

本机 `工作区\` 已经注册成 workspace（`workspace/create`），所以现在建会话会正常分组。若换目录：先在界面里打开该目录，或先调一次 `workspace/create`。

## 5. 踩到的坑（症状 → 原因）

| 症状 | 原因 | 已怎么处理 |
|---|---|---|
| 双击后秒退、没有任何窗口 | 从 DSH 环境启动时继承了 `ELECTRON_RUN_AS_NODE=1`，Electron 按 Node 模式跑 `.` 就退 | 启动前清掉该变量（普通双击不受影响） |
| 停在「引擎启动失败 100%」 | 没有 `引擎\apps\cli\lib\bin.js` | 见 §3① |
| 打开就一个「预览版说明」全屏弹框 | 0.2.2 新 DSH_HOME 的首次导引 | 见 §3④ |
| 面板一直「等待登录」 | 引擎数据目录没有账号凭证 | 见 §3⑦，或手动登录 |
| `sessions.mjs --check` 全红「会话不存在」 | ① 脚本默认 `DSH_HOME=引擎\.dsh`；② 会话没挂 workspace 就不进 projcache | ① 见 §3②；② 已建 workspace 并在其中重建会话 |
| `自检.mjs` 报 Node 版本不够 | 系统 Node 22.22 < 24.9 | 用 DSH 自带 node.exe 跑自检（引擎本身不受影响，它跑在 Electron 的 Node 24 里） |
| 引擎日志 `boot-anim-host failed to import` | profile 里挂的插件没装 | 见 §3⑥ |
| `npm install` 下载 Electron 卡住 | 默认从 github 拉二进制 | `$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'`，再 `node node_modules\electron\install.js` |

## 6. 仍然跑不通 / 需要你决定的部分

### 6.1 免费网页版 AI 桥（03 板块）——缺文件，本机跑不了

外壳已经起了桥服务（`http://127.0.0.1:31239/webai/keys`），渲染层的 `webai-bridge.js` 也在，但**调用方脚本 `外壳\scripts\webai.mjs` 在本仓库里不存在**（`main.js`、`preload.js`、`README` 都引用了它）。所以「让会话去问免费网页版 AI」这条链路目前只能手工在浮动窗口里用。

要修：从作者的完整交付版补 `scripts\webai.mjs`，或照 [`03-MCP接免费AI`](../03-MCP接免费AI/) 的架构自己写一个薄的 HTTP 客户端（`POST /webai/ask {key,text,timeoutMs}`）+ 一个 MCP 包装。即便补上，各站 DOM 会随改版失效，仍需现场调试——**不建议作为第一个上手的模块**。

### 6.2 MCP 站点配置（03 板块）

`renderer\mcp-panel.js` 里那一排「网页版·DeepSeek / 豆包 / 通义 / 智谱 / Kimi」只是**面板 UI**，真正的 MCP server 配置、各站登录态、选择器都要按 [`03-MCP接免费AI`](../03-MCP接免费AI/) 自己配。模板里没有任何 MCP server 进程被拉起。

### 6.3 引擎版本漂移（0.2.1 → 0.2.2）

模板的「钉会话」靠 **DOM + localStorage 键**（`[role="treeitem"]`、`dsh.sessions.current`）。0.2.2 上实测这两样都还在、钉会话生效；但欢迎弹窗/登录弹窗是新出现的（已补）。**以后 DSH 再升级，同类失效要按这个思路补**：先用调试端口看 webview 里的真实 DOM，再改 `main.js` 的 `HARNESS_FIX_JS` 或 `renderers.js` 的 `HARNESS_PIN_JS`。

### 6.4 场景里依赖外部的部分

- **个人站里的 DeepSeek 网页版**：`<webview>` 打开后要登录一次（登录态在该面板的分区里，会持久化）。（自我复盘里的 DeepSeek 网页版卡片已移除）
- **自我复盘**：根目录默认 `12-源码照搬\自我复盘`（里面只有一份 README），要换成你的资料目录就设 `REVIEW_DIR`。
- **本地电脑**：磁盘扫描走系统接口，若某些分区读不到会显示空，属权限问题，不影响其它面板。
- **个人站**：`SITE_DIR` 默认指向本夹根，模板没带官网工程，顶栏那几个外链按钮走网络。

### 6.5 打包/发布脚本

`工具\封装.mjs`、`发布前检查.mjs` 是给作者完整目录结构写的，本机这份 `引擎\` 是适配层，打包前要先换回真引擎；不打算出包可以不管。

## 8. 新增：「个人站」演示场景（按参考图复刻版式）

按参考图（浅色暖调）做了一套**能用的面板**，截图见 [`../配图/孟菲斯-个人站.png`](../配图/孟菲斯-个人站.png)。

### 8.1 它由什么组成

| 面板 | 渲染器 | 数据来源 |
|---|---|---|
| 首页概览 | `ps-home` | 近 7 天 Token / 交付 / API 请求柱状图 + 吃 Token 大户 + 账户充值余额（`ps:home` / `ps:balance`） |
| 最近文件 | `ps-recent` | 「命令」页记忆神经元里 `📁 文件夹…` 打开的目录下、最近修改的文件（主进程 `ps:recent-files`） |
| 本地文件 | `ps-files` | 已归档项目（判定见 §8.6）：项目名 + 对话数 + 消耗 token（`ps:archived`） |
| 项目管理 | `ps-projects` | 控制室里的项目（桌面 DSH `workspace.json`），按最后一次对话时间倒序（`ps:projects`） |
| AI对话助手个人版 | `harness` | 会话「个人站」`session-9c819137-…` |

- 场景文件：`外壳\scenarios\personal-site.json`（12 列 × 7 行网格；文件名必须 = `id`）。
- 渲染器：`外壳\renderer\renderers.js` 里 `ps-*` 那一段（**约 140 行，顶层全用 var**，否则热更新会整块失效）。
- 样式：`外壳\renderer\styles.css` 末尾 `#grid[data-scenario="personal-site"]` 那一段（**只作用于本场景**）。

### 8.2 为什么这几个面板是新写的

公开版的「站点族」是 `site-preview / site-folder / site-projects / site-urls` 那一套（深色、接真实目录与站点），没有「首页概览 / 最近文件 / 本地文件 / 项目管理」这几种。这几块是自写的轻量渲染器：版式与 CSS 不动，数据改成从 `window.app.ps` 拿（主进程读桌面版 DSH 的 `workspace.json` 与会话日志），旧进程没有 `window.app.ps` 时面板会显示一句提示、不会白屏。

### 8.3 附带做的三处机制改动

1. **场景级外观**（`renderer.js` 的 `loadScenario`）：`#grid` 上写 `data-scenario`，CSS 才能只给一个场景换皮；同时支持 json 里的 `"theme": "light"`——进入本场景切浅色、离开还原。`01-场景模式/场景配置格式.md` 里 `theme` 已从「预留字段」改成「按场景生效」。
2. **启动加载页兜底**（`renderer.js` 的 `init`）：窗口比引擎晚就绪、或 ready 事件在监听前发过时，原来会**永远停在 92% 的加载页**（本机实测）。现在启动后自查一次 `isHarnessReady()`，就绪就主动进界面。
3. **引擎 0.2.2 会话列铺满**（`renderers.js` 的 `HARNESS_WIDE_CSS` + `main.js` 同名副本）：0.2.2 把会话放进 grid 第 2 列并钉死 435px，宽面板里会话会挤在右边、左边空一大片。补了两条：`--dsh-conversation-column-width` 压成 100%，以及 `[class*="centerCol"] { grid-column: 1 / -1 }`。

> 这三处都带注释，改回即可还原；`main.js` 的两条要**重启应用**才生效，`renderer.js` / `renderers.js` / `styles.css` 的改动点一下顶栏 ⟳ 或重载页面就生效。

### 8.4 怎么换成你自己的

1. 改名字/图标：`personal-site.json` 的 `name`（标签栏文字）、各面板 `title`（标题栏文字）。
2. 换数据：改各面板的 `data`（数组结构见文件）；或按 8.2 把取数那几行接到你的目录/接口。
3. 改版式：调 `col/row/w/h`（12 列网格）；不满 12 列时记得同步 `cols`。
4. 换 AI 会话：`node 外壳\scripts\建会话.mjs --title "个人站"`，把打印的 id 写进 `ps-ai` 的 `sessionId`。
5. 想去掉：删 `personal-site.json` 即可，其它场景不受影响（这套是自包含的）。
6. 想**开机默认进个人站**：改 `外壳\renderer\customer-start.js` 顶部的 `var FIRST = 'command'` → `'personal-site'`（改完重载页面）。

- 皮肤文件：[`外壳\renderer\memphis.css`](外壳/renderer/memphis.css)（**纯叠加层**，`styles.css` 一行没改）
- 落地说明与回退：[`孟菲斯改造说明.md`](孟菲斯改造说明.md)
- 验收图：[`../配图/孟菲斯-场景总览.png`](../配图/孟菲斯-场景总览.png) · [`../配图/孟菲斯-个人站.png`](../配图/孟菲斯-个人站.png)

顺手修的两个渲染问题（与皮肤无关、但换肤后才暴露出来）：

1. **神经元面板画布可能只有 320×240**：面板在隐藏视图里创建时量不到尺寸，ResizeObserver 又没补上 ⇒
   整张图缩成一小团。现在启动后 5 秒内反复校尺寸，量到真实尺寸就重画。
2. **节点坐标出现 NaN 会让整帧报错**：`createRadialGradient` 直接抛异常，面板只剩一行红字。
   现在 `project()` 会把坏点钉在画面中心，宁可少画一个点也不让整张图消失。

> 回退：删掉 `外壳/renderer/index.html` 里 `<link rel="stylesheet" href="memphis.css" />` 这一行，
> 重新加载界面即可；外观开关会自动恢复。
