# 命令页的 DSH 直连桌面版（同步你的对话）

> 2026-11-24 新增。目标：工作台「命令」场景里那块 AI 面板，看到的**就是你桌面版 DeepSeek Harness 的同一批工作区/对话**；其它场景（本地电脑 / 个人站 / 自我复盘）仍然各用各的工作区，互不影响。

## 1. 为什么要单独做

DSH 的会话/工作区存在**本地数据目录**里，不随账号走：

| 实例 | 数据目录 | 工作区 |
|---|---|---|
| 桌面版 DSH（你日常用的那个） | `%USERPROFILE%\.dsh` | Rcode、金融监管、金融工程、ai&人工智能、正能量阿陈的工作台 … |
| 工作台内置引擎 | `12-源码照搬\引擎数据\.dsh` | 工作区、人工智能（给其它场景用） |

所以"登同一个账号"不会让两边对话自动同步——必须让面板直接连到桌面版这台 DSH 的 Web 服务上。

## 2. 实现方式

1. 桌面版 DSH 自带一个只监听 `127.0.0.1` 的 Web 服务（端口每次启动随机）。
2. 它用「进程级随机 launch token + 签名 Cookie」鉴权。launch token 不落盘，但签名密钥
   `client-connection/browser-session` 明文存在 `%USERPROFILE%\.dsh\.credentials.yaml`。
3. 工作台按它自己的算法，为**当前桌面端端口**签一枚 24 小时有效的 v1 会话 Cookie
   （`dsh-auth-<sha256(authority)>`），写进「命令」面板 webview 的独立会话分区，然后加载
   `http://127.0.0.1:<桌面端端口>/`。
4. 于是这块面板就成了桌面版 DSH 的**第二个窗口**：同一份数据、同一个进程、实时双向——
   在面板里发消息会写进桌面版同一个会话，反之亦然。
5. 自动打开桌面版当前会话：从桌面版的 Local Storage 读 `dsh.sessions.current`，注入面板后刷新；
   每 8 秒跟一次，桌面版切会话，面板跟着切（会刷新一次面板）。

## 3. 配置 / 回退

- 只对场景 json 里写了 `"harnessSource": "desktop"` 的面板生效（目前仅 `scenarios/command.json` 的 `cmd-chat`）。
- 去掉这个字段 → 该面板回到工作台自己的引擎（`127.0.0.1:3080`），与以前一样。
- 其它三个场景的 AI 面板没有这个字段，保持隔离。

## 5. 皮肤是"只给工作台这一块"的

- 面板虽然连的是桌面版服务，但样式是按**客户端**注入的：工作台只往自己这个 webview 里 `insertCSS`
  （`data-mem-theme` + `MEMPHIS_ENGINE_CSS`），桌面版 DSH 自己的窗口是另一个客户端，**完全不受影响**。
- 标题栏「孟菲斯」开关只作用于工作台里的 DSH（主界面 + 各面板 + 这个直连面板）；关掉后这个面板回到 DSH 原版配色，桌面版依旧不变。
- 反过来说：在桌面版里改主题/换皮肤，也不会影响工作台这块面板（两边各算各的）。

## 6. 限制与注意

- **桌面版 DSH 必须开着**：没开时命令页会显示「直连桌面版 DSH 失败」+ 重试按钮。
- 桌面版**重启后端口会变**：在命令页点一次「重新加载」即可重新发现并重签 Cookie。
- 面板每 8 秒同步一次「桌面版当前会话」；如果你正在面板里打字，恰好桌面版切了会话，面板会刷新（草稿建议先发）。
- 依赖 DSH 的内部实现（`.credentials.yaml` 的键名、Cookie 算法 `v1`）；DSH 大版本升级后如果改了鉴权，这里需要跟着改。
- 只在本机回环（127.0.0.1）上使用；密钥文件只读，不写回。
- 不改变桌面版自己的窗口/数据；面板只是第二个客户端。
